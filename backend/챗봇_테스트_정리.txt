- 모델 호출은 모의 응답으로 대체하지 않음. DB 세션만 읽기 전용 트랜잭션으로 바꾸고 SELECT 이외 실행을 차단하는 테스트 보호 장치를 적용함.

- 공항 원문을 location_sources로 추출하고 실제 질문에 있는 표현인지 확인함. 한글 정규화·접미사·별칭·오타 후보를 처리함.
- 코드 없는 공항은 후보에서 제외함. 도시·국가·등록 지역은 여러 공항을 묶어 조회하며 특정 공항 하나로 임의 축소하지 않음.
- 갈 수 있는 목적지 목록은 조건에 맞는 예약 가능 항공편의 공항을 중복 없이 조회함.
- 미지원 사유 코드를 상담원 말투의 서버 안내로 연결함. 결과 없음 안내는 실제 적용 조건에 맞춰 구성함.
- 일부 명백한 날짜 오류·공격·미지원 요청은 Gemini 호출 전에 처리함. 정규식 검사는 모든 자연어 의도를 완벽하게 검증하는 수단은 아님.
- 챗봇의 실제 MySQL 조회를 START TRANSACTION READ ONLY로 시작하고 종료 시 롤백함. 일반 예약 세션에는 적용하지 않음.
- frontend-demo에서 context 전달·오류 후 유지·새 대화 초기화·내보내기를 반영함.

- 가을 여행 할인: 10%, 2026-11-01 00:00:00 ~ 2026-11-30 23:59:59
- 연말 여행 할인: 15%, 2026-11-01 00:00:00 ~ 2026-12-31 23:59:59
- 겨울 여행 할인: 20%, 2026-11-01 00:00:00 ~ 2027-01-31 23:59:59
한국 시각 기준임. 현재 DB에 ID 1, 2, 3으로 추가했으며 삭제하지 않음.
database/seed_promotions.sql을 제공함. 같은 이름이 있으면 추가하지 않으며 기존 내용을 덮어쓰지 않음.
예약 한 건에 하나만 적용함. 할인 적용 최저가 비교나 중복 할인 기능을 새로 구현한 것은 아님.

7-3. 검증 결과

수정 과정에서 실제 챗봇 API 57회 요청함. HTTP 상태별 결과: {200: 53, 503: 4}.
요청은 동시 실행하지 않고 최소 7초 간격으로 순차 진행함. 일부 요청은 서버에서 즉시 처리하여 모델을 호출하지 않음.
Gemini 일시 장애 503도 원본 기록에 보존함. 가격 정렬 후속 질문은 당시 요청·history·context 그대로 별도 재확인하여 성공함.
검증 로직·실제 MySQL 조회 검사 17개, 기존 예약·왕복 API 회귀 검사 32개, 프론트 단위 검사 8개를 통과함.
실제 MySQL 읽기 전용 트랜잭션에서 0행 UPDATE도 오류 1792로 거부됨을 확인함. 이어진 일반 세션의 0행 UPDATE는 허용되어 세션 간 제한이 남지 않음을 확인함. 두 검사 모두 데이터 변경은 없음.
브라우저에서 모의 API로 20턴의 context 전달·오류 후 보존·새 대화 초기화·JSON/텍스트 내보내기를 확인함.
수정 전 70개 전체를 다시 실행한 결과는 아님. 실패 유형과 주요 검색·예약 회귀를 중심으로 확인함.
하와이·영국·부산 일부 조회의 결과 0건은 현재 DB의 예약 가능 항공편 기준임. 공항 인식 실패와 구분함.
D10 문자열은 수정 후 서버에서 조회 없이 거절됨. 실제 DROP을 격리 DB에서 실행한 검증은 여전히 수행하지 않음.
